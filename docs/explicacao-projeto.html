De onde vem a população do seu quarteirão?

O IBGE só sabe responder por bairro inteiro. Este projeto ensina o mapa a responder por pedaço de bairro — e já existe uma primeira peça dele rodando: o mapa interativo que você vê hoje.

O problema

1As divisões oficiais não batem com a cidade real

Prefeitura e IBGE mapeiam os dados da cidade em bairros e setores censitários. Mas quem mora lá pensa em loteamentos — pedaços menores, com dados próprios.

Mesma área da cidade, três formas diferentes de dividi-la.

O que existe oficialmente

O Censo do IBGE conta pessoas por setor censitário. A prefeitura organiza os dados dos serviços normalmente por bairro. Nenhum dos dois é o loteamento onde as pessoas moram.

Por que isso é um problema conhecido

Isso tem nome na literatura: MAUP (Problema da Unidade de Área Modificável). A forma como você desenha as fronteiras muda o que os números parecem dizer.

Por que isso importa

2Bairro inteiro esconde onde o problema realmente está

Imagine decidir onde abrir uma nova escola. Olhando só a média do bairro, tudo parece equilibrado. Olhando loteamento por loteamento, aparece um bolsão de gente sem vaga — escondido dentro da média.

O mesmo bairro, mas agora dá para apontar exatamente qual loteamento precisa de atenção.

A proposta

3Não inventamos gente nova — redistribuímos a que já existe

O Censo já diz quantas pessoas moram em cada setor. O trabalho não é adivinhar esse total — é decidir, dentro do setor, quanto cabe a cada loteamento que o sobrepõe.

Loteamento com mais endereços cadastrados recebe fatia maior da população do setor — não a mesma fatia pra todo mundo.

Por que endereços, e não área? Porque um loteamento pode ser pequeno e denso, ou grande e vazio. Contar quantas casas existem é uma aproximação melhor de "quanta gente mora ali" do que simplesmente medir o terreno.

Honestidade dos dados

4O que sobra é mostrado, não escondido

Nem toda área de um setor pertence a um loteamento mapeado — pode ser zona rural, terreno vazio, ou um loteamento que ainda não foi cadastrado. Em vez de distribuir essa sobra escondida entre os vizinhos, o método reporta esse resíduo explicitamente.

Essa sobra vira um número visível na plataforma — não um erro escondido na média.

JÁ EXISTE — RODANDO HOJE

6MVP

Em vez de esperar o banco de dados e a API ficarem prontos, o projeto começou pela ponta que o usuário final realmente vê: o mapa. A pergunta que essa etapa responde é: "a ideia de navegar por bairro → loteamento → setor, com transparência sobre incerteza, funciona bem na prática, num navegador comum?"

O que dá pra fazer no mapa hoje
  • Navegar em três níveis: bairro → loteamento → setor censitário (a malha do IBGE, usada como camada de referência)
  • Clicar num bairro e ver os prédios subirem em 3D, com a ficha de loteamentos daquela área
  • Buscar qualquer lugar pelo nome, com destaque instantâneo
  • Alternar entre temas
  • Ver, no próprio polígono, quando um loteamento tem geometria "não confirmada"
Como os dados chegam hoje

Sem banco de dados ainda. Um script (prepare-data.mjs) lê os arquivos brutos, calcula a qual bairro cada loteamento pertence e grava arquivos GeoJSON estáticos, que o navegador busca diretamente — fazendo hoje, localmente, o papel que a ETL + MongoDB + API farão depois.

Os campos "inventados", e por quê

O campo de confiabilidade de cada loteament, no momento, é um MOCK. Ele existe só para provar que a interface consegue comunicar incerteza visualmente — exatamente o requisito levantado na fundamentação teórica sobre visualização de incertezas espaciais.

PRÓXIMA ETAPA

7O que falta para fechar o pipeline

O mapa já prova que a ponta visual funciona. As próximas etapas plugam dado real nela, sem precisar redesenhar a interface:

  • Rodar a ETL real em Python: cruzar setores do IBGE, endereços do CNEFE e as geometrias de loteamento
  • Substituir os arquivos estáticos por MongoDB + uma API REST que sirva GeoJSON sob demanda
  • Trocar o campo de confiabilidade "inventado" pela validação geométrica de verdade (sobreposição, cobertura, resíduo)
  • Caso prático - conectar a população estimada por loteamento ao Censo Escolar do INEP, para demonstrar o ganho prático de granularidade
